# Campaign v2 preregistration

Registered 2026-10-19 before v2 candidate generation or any held-out API call. The review revisions in ops/expansion-plan.md govern this campaign. V1 is preserved in tasks/archive/v1-20261017 and its original result directories.

The targets are 300 held-out search tasks from at least 10 sources, 300 scrape tasks from at least 20 sites, 60 map tasks from at least 15 sites, and 40 crawl tasks from at least 12 sites. Real-web minima are 100%, 85%, 80%, and 75%. Candidate and verification failures are recorded; shortfalls must be disclosed rather than filled with invalid tasks. Registry versions, release facts, absent releases, and independent documentation sites expand the population. Page titles and headings are read from authoritative HTML; registry facts come from official JSON APIs. No Wikipedia/Wikidata scrape key is accepted without page agreement.

Keep the existing deterministic 30% dev split, including cross-track answer isolation. New registry search/scrape pairs and documentation map/crawl pairs share a split. Pilots use dev only. Samples are frozen after dev adapter fixes, with SHA-256 hashes, instructions, oracle evidence hashes, and provenance. No frozen test task is edited. Exclude invalid candidates before freezing. All frozen files must pass independent live verification, including input/instruction equality, page counts no greater than maxPages and 30, and output feasibility: canonical answer JSON at most 4,096 UTF-8 bytes (a conservative 4,096-token upper bound), crawl oracle package at most 48,000 bytes. Scrape oracle evidence must fit 12,000 bytes and contain all keyed answers. Rendered scrape candidates require independent browser evidence; unverified JS targets are excluded and the resulting share/shortfall disclosed. Do not invent JS verification.

Seed 19019 controls runner ordering; seed 19020 controls stratified selection, without consulting provider outcomes. Select families round-robin and sites within families, preferring unused sites, then underrepresented sites. Starting core sizes are search 30, scrape 40, map 15, crawl 12. Search/scrape cores permit at most 3 tasks per site/source; map/crawl at most 2. Minimum core clusters are 10/15/10/8 respectively. Search, map, and crawl use 100% real-web tasks. Scrape includes six independently browser-verified, seeded JS candidates, split by the existing 30% rule into two dev and four held-out tasks. Freeze two JS tasks in the 40-task core (5% JS, 95% real-web), and four in the 300-task full set (1.33% JS, 98.67% real-web). If the full set falls short of 300, retain the four verified JS tasks and report the exact resulting share, still requiring at least 85% real-web. These requirements apply to the actual frozen sample. If the pool cannot meet a core minimum, that track cannot run as a headline comparison. Never relabel individual projects on one registry as independent sources.

All eligible providers in a track receive identical core IDs. Budget-limited providers run core only; affordable providers run full, containing the entire core. Eligibility requires every core ID to have a completed graded result; an unfinished core means not run for headline ranking, with the reason. Failures, including retrieval failures, still count as completed graded attempts. API budget stops do not. Raw and agent modes share the existing exact-argument first-call reuse. Full-set scores are separately labeled and never used to select a headline reference.

The agent remains Claude Haiku 5.5, temperature 0, 4,096 output tokens, neutral prompt and tool, and existing per-track deadlines/call limits. Script grading only. No-tool controls cover each full held-out sample; independent correct-page controls cover scrape. Run default lanes only. Audit native title forwarding and rendering on dev tasks; retain product rendering defaults and disclose differences. Crawl native document titles are evidence and should be forwarded uniformly when returned. No adapter/harness fixes after test calls; a necessary correction requires a separately disclosed campaign, not editing a completed test run.

Context.dev, Spider, and all other providers use concurrency 1; other endpoint spacing is 1 second. The runner has at most 4 workers. No retry outside existing bounded model transport retries.
